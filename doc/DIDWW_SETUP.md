# Подключение DIDWW — настройка и важное ограничение архитектуры

## 1. Регистрация и получение API-ключа

1. Зарегистрироваться на [didww.com](https://www.didww.com/) (кнопка "Sign up").
2. Войти в DIDWW User Panel → раздел **API**.
3. Создать API-ключ: указать имя ключа и обязательно включить опцию
   **Enable callbacks** — без неё вебхуки о смене статуса заказа приходить не будут.
4. Для тестирования нужен ключ в **sandbox**-окружении — он выдаётся отдельно
   через обращение в DIDWW Technical Support (в отличие от production-ключа,
   sandbox не создаётся самостоятельно через панель).
5. Вставить ключ в `backend/.env`:
   ```
   DIDWW_API_KEY=ваш_ключ
   DIDWW_ENVIRONMENT=sandbox   # или production
   ```

## 2. Пополнение баланса

Как и с Telnyx — без баланса заказ DID не пройдёт. Пополнение — в разделе
**Billing** DIDWW User Panel.

## 3. Как работает провижининг в этом проекте

Кнопка "Добавить номер" → DIDWW в выпадающем списке вызывает следующую
цепочку (`backend/src/didww/`):

1. `GET /v3/countries?filter[iso]=UA` — находим Украину в покрытии.
2. `GET /v3/did_groups?filter[country.id]=...&include=stock_keeping_units` — берём первую доступную DID Group и её SKU (тариф).
3. `POST /v3/orders` — заказываем 1 номер по этому SKU, передаём `callback_url` на `/api/didww/webhooks/order-status`.
4. Если заказ завершился синхронно (`status: "Completed"` в ответе) — сразу запрашиваем `GET /v3/dids?filter[order.id]=...`, чтобы узнать назначенный номер.
5. Если заказ ещё обрабатывается (`status: "Pending"`) — создаём в своей БД запись-плейсхолдер (карточка покажет "Номер уточняется…", статус "Ожидание") и ждём вебхук.

## 4. Важное упрощение — требует проверки перед продакшеном

DIDWW документирует HMAC-SHA1 подпись коллбэков (сортировка параметров +
подпись API-ключом), но:

- **Проверка подписи в `didww.webhook.controller.ts` пока не реализована.** Как и было с Telnyx изначально — сейчас это просто TODO, а не готовая защита. Перед продакшеном обязательно добавить проверку по документации DIDWW (Callbacks Details), иначе кто угодно сможет дёрнуть `/api/didww/webhooks/order-status` и подделать статус заказа/номера.
- **Точная структура тела вебхука не проверена на реальном сэндбоксе.** Код ожидает поля `{ id, status }` в теле POST-запроса — это наиболее вероятная структура по документации, но нужно подтвердить реальным тестовым заказом перед тем, как полагаться на это в проде.

## 5. КРИТИЧЕСКИ ВАЖНО: DIDWW не даёt возможности звонить программно

**Это главный архитектурный момент, который нужно понимать.**

DIDWW — это провижининг номеров (DID) и SIP-транкинг для их терминации.
У DIDWW **нет** REST-эндпоинта вида "позвони на этот номер" — в отличие от
Telnyx Call Control API. Чтобы физически позвонить с DIDWW-номера, нужно:

1. Создать **Voice OUT Trunk** в DIDWW User Panel (SIP-транк с логином/паролем или IP-аутентификацией).
2. Поднять свою SIP-инфраструктуру (SBC, Asterisk/FreeSWITCH, или SIP-стек в коде), которая зарегистрируется на этом транке и сама пошлёт SIP INVITE.
3. Самостоятельно реализовать проигрывание озвучки через эту SIP-сессию (RTP-поток) — то есть весь функционал, который у Telnyx даёт `playback_start` одной строкой, здесь нужно строить с нуля на уровне медиа.

**Из-за этого в проекте сейчас стоит защита**
(`calls.service.ts`): пробный звонок с озвучкой ищет активный номер **только
с `provider: 'telnyx'`**, и если таких нет — возвращает понятную ошибку,
а не пытается (и не может) позвонить через номер DIDWW.

### Итог по DIDWW-номерам сейчас

| Что работает | Что не работает |
|---|---|
| Заказ номера через API | Исходящий звонок с этого номера через текущий проект |
| Отображение в пуле номеров (карточка, статус active) | Проигрывание озвучки на этом номере |
| Хранение провайдера/ID номера в БД | Всё, что требует медиа-потока — этого пока нет для DIDWW вообще |

Если нужно реально звонить с DIDWW-номеров — это отдельная, значительно
более объёмная задача (SIP-стек или интеграция вроде Kamailio/FreeSWITCH,
которая регистрируется на DIDWW Voice OUT Trunk), не решаемая одним REST-клиентом
по аналогии с Telnyx.
