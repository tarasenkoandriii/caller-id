# Подключение к Telnyx — пошаговая инструкция

Эта инструкция покрывает всё, что нужно сделать в аккаунте Telnyx, чтобы
проект `caller-id` заработал: регистрация, API-ключ, пополнение баланса,
SIP Connection, заказ номера, вебхуки. В конце — таблица соответствия шагов
переменным окружения из `backend/.env`.

---

## 0. Мультиаккаунт — несколько Telnyx-аккаунтов одновременно

Проект поддерживает несколько независимых Telnyx-аккаунтов одновременно —
у каждого свой API-ключ, свой Call Control Application и свой набор номеров.
Управление — во вкладке админки **"Telnyx"**:

- Карточка на каждый аккаунт: баланс, статус Call Control Application, число номеров в пуле, кнопки "Включить/Отключить" и "Удалить".
- Кнопка "Добавить аккаунт" сверху справа — форма с полями: название, API Key, Connection ID (получаются так же, как описано в разделах 2 и 4 ниже, просто повторяете эти шаги для каждого нового Telnyx-аккаунта).
- Плашка сверху — суммарный баланс по всем аккаунтам, общее число номеров в пуле, сколько Call Control Application сейчас реально активны.

**Как выбирается аккаунт при заказе номера или звонке:** по умолчанию
используется первый **включённый** аккаунт (по дате добавления). Явный выбор
конкретного аккаунта под конкретный заказ номера пока не реализован в UI —
это следующий шаг, если нужно.

**Обратная совместимость:** пока во вкладке "Telnyx" не добавлено ни одного
аккаунта, всё работает по-старому — через `TELNYX_API_KEY` и
`TELNYX_CONNECTION_ID` из `.env` (см. разделы 2 и 4). Как только появляется
хотя бы один аккаунт в таблице — эти переменные окружения больше не
используются.

## 0.1 VPN/прокси для запросов к Telnyx (чекбокс во вкладке "Telnyx")

Рядом с кнопкой "Добавить аккаунт" есть чекбокс **"Использовать VPN для
запросов к Telnyx"**. По умолчанию выключен. При включении **все** запросы
`TelnyxClient` (баланс, заказ номеров, звонки, всё) идут через
прокси-диспетчер (`undici.ProxyAgent`) — тот же паттерн, что уже
используется в проекте cargo-tracker для CargoAI.

**Если в `.env` нет ни одной из нужных переменных — чекбокс задизейблен и
принудительно выключен**, даже если в базе когда-то было сохранено значение
"включено" (защита от рассинхронизации при переезде между окружениями).

Настроить можно тремя способами (первый найденный побеждает):

1. `TELNYX_PROXY_URL` — готовый URL вида `http://user:pass@host:port` от любого прокси-провайдера.
2. Webshare (удобно, если не хочется вручную собирать URL) — залогиниться на [dashboard.webshare.io/proxy/settings](https://dashboard.webshare.io/proxy/settings), скопировать логин/пароль в:
   ```
   WEBSHARE_PROXY_USERNAME=
   WEBSHARE_PROXY_PASSWORD=
   ```
   Опционально: `WEBSHARE_PROXY_COUNTRY` (например `us`), `WEBSHARE_PROXY_PORT` (по умолчанию 80), `WEBSHARE_PROXY_ROTATE=false` (по умолчанию `true` — новый выходной IP на каждый запрос).
3. Обычные `HTTPS_PROXY` / `HTTP_PROXY` — если прокси уже настроен на уровне окружения (например, через хостинг).

Переключение чекбокса сразу пересобирает диспетчер в уже запущенном
процессе — перезапуск бэкенда не требуется. При холодном старте (например,
после деплоя на Vercel) сохранённое в БД состояние подхватывается заново
автоматически.

## 1. Регистрация аккаунта

1. Перейти на [telnyx.com/sign-up](https://telnyx.com/sign-up).
2. Заполнить форму: контактные данные, название компании, надёжный пароль.
3. Подтвердить email — перейти по ссылке из письма от Telnyx.
4. Войти в [Mission Control Portal](https://portal.telnyx.com/) под новым аккаунтом.

Новые аккаунты получают бесплатные тестовые кредиты — можно опробовать
платформу до того, как привязывать способ оплаты.

---

## 2. Получение API-ключа (`TELNYX_API_KEY`)

API-ключ — это bearer-токен для всех запросов к `api.telnyx.com/v2/*`.

1. В Mission Control Portal нажать на своё имя/аватар в правом верхнем углу.
2. Выбрать **Account Settings** → **API Keys** (либо сразу пункт **API Keys** в меню аккаунта).
3. Нажать **Create API Key** в правом верхнем углу.
4. В диалоге создания указать понятный тег, например `caller-id-production` или `caller-id-dev`, и настройки срока действия (можно оставить бессрочным для начала).
5. Нажать **Create**.
6. **Важно:** полное значение ключа показывается только один раз, сразу после создания. Скопировать его сразу и сохранить в менеджере паролей — просмотреть повторно будет нельзя, только сгенерировать новый.
7. Вставить значение в `backend/.env`:
   ```
   TELNYX_API_KEY=KEY_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
   ```

**Рекомендации по безопасности от Telnyx:**
- Никогда не коммитить ключ в git — он уже в `.gitignore` через `.env`.
- Использовать разные ключи для dev и production.
- Периодически ротировать ключи для продакшн-аккаунтов.

---

## 3. Пополнение баланса

Без баланса нельзя ни купить номер, ни совершить звонок.

1. В Mission Control Portal найти зелёную иконку **+** в верхней панели (пополнение баланса) или раздел **Billing**.
2. Для тестового старта достаточно $5–10 — это покроет покупку 1–2 номеров Украины (от $1) и несколько минут исходящих тестовых звонков.
3. Привязать карту или другой поддерживаемый способ оплаты.

Баланс аккаунта потом будет виден прямо в админке (вкладка "Номера") — бэкенд запрашивает его через `GET /v2/balance`.

## 4. Создание Call Control Application (`TELNYX_CONNECTION_ID`)

**Важно:** для программных звонков через Call Control API (именно так этот
проект делает тестовые звонки — `POST /v2/calls`) нужен не обычный SIP
Trunking Connection, а отдельная сущность **Call Control Application**
(она же "Voice API Application"). Это частая путаница — попытка использовать
`connection_id` от SIP Trunking-коннекшена для команд Call Control вернёт
ошибку авторизации.

1. В меню портала: **Voice → Programmable Voice → Voice API Applications** (или **Connections → +Add Connection** → тип **Call Control**, в зависимости от версии портала).
2. Нажать **Create Voice API Application** / **Create Call Control App**.
3. Указать имя, например `caller-id-callcontrol`.
4. В поле **Webhook URL** указать любой временный адрес для первичного сохранения (проект передаёт актуальный `webhook_url` программно в каждом запросе `POST /calls`, так что значение здесь используется только как fallback).
5. Сохранить — приложению присвоится **Application ID** (это и есть `connection_id` для API).
6. Скопировать его в `backend/.env`:
   ```
   TELNYX_CONNECTION_ID=1234567890
   ```

### 4.1 Создание Outbound Voice Profile (обязательно для исходящих)

Без этого шага исходящие звонки будут отклоняться с ошибкой `403 Dialed
Number is not included in whitelisted countries`, даже при достаточном
балансе.

1. **Voice → Outbound Voice Profiles → +Add New Profile**.
2. Указать имя, например `ua-outbound`.
3. В разделе **Allowed Destinations** добавить **Ukraine** (по умолчанию разрешены только США/Канада).
4. В разделе **Connections/Applications** нажать **Add connections/apps to profile** и отметить галочкой созданное на шаге 4 приложение `caller-id-callcontrol`.
5. Сохранить.

### 4.2 Привязка номера к приложению

1. Открыть настройки приложения `caller-id-callcontrol` → вкладку **Numbers**.
2. Отметить купленный украинский номер(а), чтобы приложение могло использовать их как `from` при исходящих звонках.
3. Сохранить.

Если этот шаг пропустить, `POST /calls` с `from`, не привязанным к
приложению, тоже может быть отклонён — зависит от настроек аккаунта, но
привязка снимает эту неопределённость.

---

## 5. Заказ украинского номера

В проекте это делается автоматически кнопкой **"Добавить номер"** во вкладке
"Номера" (эндпоинт `POST /admin_panel_2026/telnyx/numbers/order`), но для
понимания — вот что происходит внутри на стороне Telnyx:

1. `GET /v2/available_phone_numbers?filter[country_code]=UA` — поиск доступного номера.
2. `POST /v2/number_orders` — заказ найденного номера с привязкой к `connection_id`.
3. Активация занимает от нескольких секунд до часов — Telnyx уведомляет о завершении заказа через вебхук `number_order.completed` (см. следующий раздел).

Если нужно сделать это вручную через портал (для проверки, что аккаунт вообще может покупать номера Украины):
1. **Numbers → Buy Numbers**.
2. Страна: **Ukraine**, тип: **Local**.
3. Выбрать номер из списка → **Buy**.
4. На вкладке номера указать **Connection**, к которому его привязать.

## 6. Настройка вебхуков

### 6.1 Вебхук заказа номера

1. **Account Settings → Webhooks** (или прямо на странице конкретного number order — Telnyx позволяет задать webhook URL глобально на аккаунт).
2. Указать URL:
   ```
   https://<ваш-backend-домен>.vercel.app/telnyx/webhooks/telnyx
   ```
   (без префикса `/admin_panel_2026` — этот путь специально вынесен из-под общего префикса роутинга, см. `backend/src/main.ts`).
3. Сохранить.

### 6.2 Публичный ключ для проверки подписи (`TELNYX_WEBHOOK_PUBLIC_KEY`)

Telnyx подписывает каждый вебхук Ed25519-подписью (заголовки
`telnyx-signature-ed25519` и `telnyx-timestamp`), чтобы бэкенд мог убедиться,
что запрос действительно пришёл от Telnyx, а не от третьей стороны.

1. В том же разделе **Webhooks** найти **Public Key** — она отображается рядом с настройками вебхука.
2. Скопировать значение (обычно длинная base64-строка) в:
   ```
   TELNYX_WEBHOOK_PUBLIC_KEY=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
   ```
3. Если оставить переменную пустой — бэкенд пропустит проверку подписи (удобно для локальной разработки через `curl`, но **обязательно заполнить в продакшене**).

### 6.3 Вебхук звонков

Отдельно в портале настраивать не нужно — URL передаётся программно в
каждом запросе `POST /v2/calls` как поле `webhook_url` (см.
`backend/src/calls/calls.service.ts`). Он строится из переменной
`PUBLIC_BACKEND_URL`:
```
PUBLIC_BACKEND_URL=https://<ваш-backend-домен>.vercel.app
```
Из неё бэкенд собирает `https://<домен>/calls/webhooks/telnyx-call` для
каждого нового звонка.

**Важно:** пока `PUBLIC_BACKEND_URL` не задан или указывает на `localhost`,
Telnyx физически не сможет достучаться до вебхука — тестовые звонки с
проигрыванием озвучки работают только на задеплоенном бэкенде с публичным
доменом (или через туннель типа ngrok при локальной разработке).

---

## 7. Проверка через софтфон (опционально, для отладки SIP напрямую)

Если нужно убедиться, что SIP Connection в принципе работает (независимо от
Call Control API, который использует сам проект):

1. Установить любой SIP-совместимый софтфон — например [Zoiper](https://www.zoiper.com/) или MicroSIP.
2. В настройках аккаунта указать:
   - **Домен/сервер:** `sip.telnyx.com`
   - **Логин/пароль:** креды из вашего Credential Connection (не путать с API-ключом — это отдельная авторизация именно для SIP-регистрации).
3. После успешной регистрации в софтфоне можно набрать тестовый номер и убедиться, что звонок проходит через ваш баланс и коннекшен.

Для целей этого проекта (звонки инициируются программно через Call Control
API) этот шаг не обязателен, но полезен, если что-то не звонится и нужно
исключить проблему на уровне самого Telnyx-аккаунта.

---

## 8. Итоговая таблица: куда что вписывать

| Что получили в Telnyx | Переменная в `backend/.env` |
|---|---|
| API-ключ из Account Settings → API Keys | `TELNYX_API_KEY` |
| ID из Voice → SIP Trunking → ваш коннекшен | `TELNYX_CONNECTION_ID` |
| Public Key из Account Settings → Webhooks | `TELNYX_WEBHOOK_PUBLIC_KEY` |
| Домен, на котором задеплоен `backend/` | `PUBLIC_BACKEND_URL` |

## Чек-лист: достаточно ли этого для реального обзвона с озвучкой

**На стороне Telnyx (портал):**
- [ ] Аккаунт зарегистрирован, email подтверждён
- [ ] Баланс пополнен
- [ ] API-ключ создан и вставлен в `TELNYX_API_KEY`
- [ ] Создан именно **Call Control Application** (не SIP Trunking Connection) — см. раздел 4
- [ ] Создан **Outbound Voice Profile** с разрешённым направлением **Ukraine** и привязан к приложению — см. раздел 4.1
- [ ] Номер куплен/заказан и привязан к приложению — см. раздел 4.2
- [ ] Вебхук `number_order.completed` настроен на `/telnyx/webhooks/telnyx`
- [ ] Публичный ключ вебхука скопирован в `TELNYX_WEBHOOK_PUBLIC_KEY`

**На стороне проекта (код и деплой):**
- [ ] `backend/` задеплоен на реальный публичный домен (не localhost) — без этого Telnyx не достучится ни до вебхука звонка, ни до mp3 в Vercel Blob
- [ ] `PUBLIC_BACKEND_URL` указывает на этот домен
- [ ] Postgres (Supabase) поднят, `DATABASE_URL` заполнен, `npx prisma migrate deploy` выполнен (включая модели `Voiceover` и `TestCallLog`, добавленные позже первой миграции)
- [ ] `VOICE_API_KEY` (ElevenLabs) и `BLOB_READ_WRITE_TOKEN` (Vercel Blob) заполнены
- [ ] Хотя бы один номер в БД проекта имеет статус `active` (иначе `POST /calls/test` вернёт ошибку "нет активного номера")

**Обновление:** проверка Ed25519-подписи теперь реализована одинаково для
обоих вебхуков (`telnyx/webhooks/telnyx` и `calls/webhooks/telnyx-call`) —
общая функция вынесена в `backend/src/common/telnyx-signature.util.ts`.
Как и раньше, при пустом `TELNYX_WEBHOOK_PUBLIC_KEY` проверка пропускается
(удобно для локальной разработки), но в продакшене переменную обязательно
нужно заполнить.

Если все пункты первого блока (Telnyx) и второго блока (деплой/БД/ключи)
выполнены — тестовый звонок с озвучкой должен пройти end-to-end так, как
описано в README (раздел "Логика пробного звонка с озвучкой").
