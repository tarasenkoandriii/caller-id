# Telegram Mini App — клиентская страница

Клиентская страница (`/`) теперь умеет работать как полноценный **Telegram
Mini App** — открывается внутри Telegram (через кнопку меню бота или
инлайн-кнопку), автоматически логинится без единого клика и использует
нативную кнопку Telegram (**MainButton**) для запуска обзвона.

**Админка (`/admin_panel_2026`) остаётся десктоп-онли** — Mini App её не
касается, туда ничего не добавлялось и адаптировать её под мобильный
WebView не требовалось.

---

## 1. Чем Mini App отличается от уже существующего Telegram Login Widget

В проекте теперь **два разных способа** войти через Telegram на клиентской
странице — это разные вещи с разным алгоритмом проверки подписи:

| | Telegram Login Widget | Telegram Mini App |
|---|---|---|
| Как открывается | Обычный браузер, кнопка "Log in with Telegram" | Внутри самого Telegram — кнопка меню бота / инлайн-кнопка |
| Откуда данные | Колбэк виджета (`onauth`) | `window.Telegram.WebApp.initData` |
| Алгоритм подписи | HMAC-SHA256, ключ = `SHA256(bot_token)` | HMAC-SHA256, ключ = `HMAC-SHA256("WebAppData", bot_token)` — **другой** |
| Нужен клик пользователя? | Да | Нет — авторизация автоматическая при открытии |
| Файл проверки на бэкенде | `telegram-auth.util.ts` | `telegram-webapp-auth.util.ts` |

Оба способа выдают один и тот же тип owner-идентификатора —
`telegram:<numeric id>` — так что если человек уже пользовался клиентской
страницей через Login Widget в браузере, а потом открыл того же бота как
Mini App, это будет один и тот же владелец данных (совпадает Telegram ID).

## 2. Регистрация Mini App в BotFather

1. Написать [@BotFather](https://t.me/BotFather) → `/newapp` (или `/mybots` → выбрать бота → **Bot Settings** → **Menu Button** → **Configure Menu Button**, если бот уже создан для Login Widget — см. `doc/TELEGRAM_LOGIN_SETUP.md`).
2. Указать URL клиентской страницы:
   ```
   https://<frontend-domain>.vercel.app/
   ```
   (корень, без `/admin_panel_2026` — это админка, её в Mini App не открываем).
3. После настройки в самом боте появится кнопка меню (обычно слева от поля ввода) — по ней и открывается Mini App.

Можно использовать **того же бота**, что и для Login Widget — Mini App и
Login Widget не конфликтуют, это просто два разных способа получить доступ
к одной и той же клиентской странице.

## 3. Как это работает технически

1. Пользователь открывает бота в Telegram → жмёт кнопку меню → Telegram открывает `https://<frontend-domain>/` внутри своего WebView, добавляя `window.Telegram.WebApp` в страницу (через `<script src="https://telegram.org/js/telegram-web-app.js">`, уже подключён в `frontend/index.html`).
2. `ClientApp.tsx` при монтировании проверяет `isInTelegramMiniApp()` — если `window.Telegram.WebApp.initData` непустой, вызывает `POST /client-bootstrap` с этим `initData`.
3. Бэкенд (`ClientBootstrapController`) проверяет подпись `initData`, выдаёт JWT и **одним ответом** возвращает токен + список номеров + озвучки + кампании + лог звонков — вместо пяти последовательных запросов после логина. Это заметно на старте именно внутри Telegram WebView, где каждый лишний round-trip ощутим.
4. Если `initData` невалиден или просрочен (старше 24 часов) — тихо откатываемся на обычный экран логина (Google/Telegram Login Widget), ничего не ломается.
5. Кнопка "Обзвонить" внутри Mini App дублируется через `Telegram.WebApp.MainButton` — нативную кнопку, закреплённую внизу экрана Telegram. Обычная HTML-кнопка в разметке никуда не делась и работает так же — на случай если MainButton недоступна (очень старые клиенты Telegram).

## 4. Локальная отладка

Как и с Login Widget и вебхуками — Telegram не откроет Mini App на
`http://localhost`, нужен HTTPS. Для локальной проверки:

```bash
ngrok http 5173
```

и временно указать полученный `https://xxxx.ngrok-free.app/` в BotFather
(`/newapp` или Menu Button) вместо боевого домена — на время отладки.

## 5. Что не потребовалось делать

- **Не адаптировали админку** — она как была desktop-only, так и осталась. Ни вкладок, ни Mini App интеграции туда не добавлялось.
- **Не заводили отдельный npm-пакет/SDK** — используется официальный `telegram-web-app.js` напрямую через `<script>`, без обёрток вроде `@twa-dev/sdk`, чтобы не тащить лишнюю зависимость ради тонкой прослойки над `window.Telegram.WebApp`.
- **Не трогали существующий Login Widget-флоу** — оба способа входа сосуществуют, ни один не заменяет другой.
